### 重要发现：global.css 用 !important 压制了组件的卡片样式
`src/styles/global.css:167-176` 的 `.card-image` / `.card-image-inner` 全带 `!important`，
而 `CharacterCard` 里同名规则没有 → **组件 `<style>` 中卡片相关规则约一半是失效的**（含刚删掉的 `.white-bg-card`）。

## YuanHuaWiki — 修掉「卡片样式两处来源」的隐患

用户问「这隐患你能修吗」→ 修了卡片这一处，并把同类隐患全站扫了一遍。

### 做法（不靠肉眼，靠级联求值）
1. 写了一个极简 CSS 解析器 + 级联求值器：对每条 `(media, selector, prop)` 算出「真实生效值」
   （规则：`!important` 优先；同级比特异性；同特异性比源码顺序）。
2. 实测加载顺序确认：`index.css`(global) 先加载，组件样式在懒加载 chunk 里后加载 → 同优先级组件赢。
3. 把两个来源的胜出值合并成单一定义，写进 `CharacterCard/index.vue`，移除全部 `!important`；从 `global.css` 删除 28 条卡片规则（317 → 215 行）。
4. **写回前先校验**：重算合并后的级联，与合并前逐条比对，126 条生效值零差异才落盘。

### 第一次失败的原因（值得记住）
- 解析器没剥离 `/* */` 注释 → 选择器被注释污染（`/* xx */ .sel`），导致校验报「丢失 1 条 + 多出 294 条」。
- 按行删除规则失败：多行规则（`.character-card { ... }`）的行匹配用的是被污染的选择器。
- 修正：解析前 strip 注释；改用「span 删除」（解析时记录每条规则在原文的起止位置，含前导空白与注释，嵌套规则的 span 加上偏移量），从后往前 splice。

### 审计结果（全站 13 个 CSS 来源 / 1704 条声明）
- 卡片（已修）曾是最大一处：126 条生效值受影响。
- `BackToTop` ✕ global.css：真冲突且有可见影响（背景渐变、过渡时长、hover 光晕环、宽高定义与实际不符）→ **未修，待用户确认**。
- `CharacterDetailLayout` ✕ global.css：18 处 `!important` 压制，其中 `.info-grid` 在 ≤640px 仍 2 列（真 bug）→ **未修，待用户确认**。
- `.empty-state`、`.footer`：重复声明但无可见差异 → 低优先级。
- 审计脚本的注意点：按「选择器字符串」比对会漏掉 `.cdl .x` vs `.x` 这类同元素的写法差异；改成按 class 集合比对后能覆盖，但会引入 `.x` vs `.x button` 的假阳性，需人工复核。跨断点的 `!important` 压制（768 打 640）任何静态审计都抓不到，必须单独查。

## YuanHuaWiki — 排查「主页卡片图片不清晰」

用户反馈主页卡片图片糊，并指出是**弗洛洛、纱雾、加奈**三张。

### 排查过程与关键结论
1. **先排除代码回归**（用户认为"以前是清楚的"）：git 逐提交比对 → db58f31（09-29）只改了 CharacterCard 的一行 `href`、删了 devServer proxy、改了 title；`global.css` 自 07-29 起未变；12 张立绘自 07-22/07-29 起未换。**卡片渲染代码与图片文件与 08-03 版逐字节一致，不存在代码回归。**
2. **构建无损耗**：`dist/assets/img/1.*.jpg` 与源文件字节数完全一致。
3. **发现格式与扩展名不符**：12 个 `1.jpg` 中 3 个是 WebP（elaina/kana/phrolova）、2 个 PNG（meguru/soyo）、1 个 AVIF（hutao），其余 6 个才是真 JPEG。**来源是 `od -An -tx1 -N4` 读文件头魔数。**
4. **分辨率不是瓶颈**：卡片图片区实测 284×379 CSS px（容器 1280 - padding 48 = 1232，4 列 gap 22）。多数立绘像素充裕；雷姆（560×880/34KB）和四糸乃（500×571）像素最少，但用户说这两张反而清楚。
5. **两个锐度指标都被证伪**：按显示尺寸归一化的边缘能量、以及"降采样再升回"的 RMSE，都受画面内容/压缩噪点干扰，**不能作为结论依据**。教训：这类判断必须看 1:1 裁切图。
6. **最终结论（离线复现卡片渲染后确认）**：糊的是**构图问题**——弗洛洛/纱雾/素世/伊蕾娜的立绘是"人物在画面里很小"的全身构图，卡片再裁一块，人物只剩很小一片。而它们的源图像素其实很富余（弗洛洛 1249px、纱雾 1753px，卡片只要 284px），**所以可以放心拉近**。加奈则是**源图被放大过**（降采样往返测试 `/2` 仅 3.44，而小鞠 6.53、纱雾 7.00），这条路修不了。

### 离线复现方法（很有用，可复用）
不启浏览器，用 Pillow 按 CSS 规则精确复现卡片实际显示：
- 盒子 284×379；按 `cardSize` 算出绘制尺寸（`cover` = `max(284/w, 379/h)` 倍；`140% auto` = 宽 1.4×284、高等比；`150% 150%` = 426×568.5）
- `background-position: top center` → 偏移 `(dw-284)/2, 0`；换算回源图坐标裁切，再 LANCZOS 缩放到目标尺寸（dpr×284）
- 拉近的**安全上限** = `源图宽 / dpr / 284`；弗洛洛 293%、纱雾 411%、加奈 376%（但加奈有效分辨率只有约一半，实际约 188%）
